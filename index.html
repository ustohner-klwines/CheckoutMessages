    Order Review

    The last page before payment. The shipments keep the names and numbers they had on the cart and the shipping page — today this page calls them “orders” — and a fee is quoted only where one exists, with a way back to the method it came from.

  • Receipt · /receipt

    Receipt

    Where shipments become real orders. Each one keeps the name and number it had through checkout and gains its own order number and a status note written for that shipment, the day counts become dates, and the rail holds the one thing still to do — schedule the delivery, or set up the RareStorage account.

Reading these

Every scenario is linkable. The toolbar writes to the query string, so any state can be sent to someone directly — the chips above are just examples.

All four checkout pages are here. The toolbar at the top of each one switches examples and links to the next page, so a scenario can be followed from cart to receipt.

The no-ZIP-code state is not in this round. Every page assumes a ZIP code is known. What the cart shows before one is entered needs more work and comes next.

Examples 2 and 3 are two shipments, not three. New York stock going to a local-delivery or pickup order is transferred to the delivering store with everything else and goes out on the same delivery or is collected at the same counter — so it is another source inside one shipment, not a shipment of its own.

Some figures are illustrative. Tax is a plausible rate per ZIP rather than a quote from the tax engine; the New York transfer timing (28 days) is a working estimate; and the receipt’s order numbers, statuses and dates are derived from those same estimates and an order placed on 21 August 2026.

Some copy is still placeholder. The pickup example's right-hand “Pickup Information” panel, and the store's street address, are stand-ins pending real content.
